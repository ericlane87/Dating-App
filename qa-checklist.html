QA Checklist

Production Readiness Test Plan

Use this page as the full test checklist before launch. The sections are grouped by user flow, risk area, and launch-critical behavior.

Goal

Catch broken flows, unsafe data access, bad UX, and cost or scale issues before launch.

Focus

Auth, profiles, dashboard, likes, chats, membership, uploads, security, and production ops.

Rule

No feature is production ready until both happy-path and failure-path behavior are tested.

User Flows Profiles Photo Uploads Dashboard Likes and Messaging Membership Security Data Integrity UX and Accessibility Performance and Launch Ops

User Flows

  • Landing page loads cleanly and all key navigation links work.
  • Sign up succeeds with valid data and blocks invalid or missing required fields.
  • Sign in works with correct credentials and fails cleanly with wrong credentials.
  • Sign out clears session state and redirects correctly.
  • Returning signed-in users are routed to the right page after login.
  • Signed-out users cannot perform protected actions.
  • Session persistence works after refresh and browser reopen.
  • Broken or expired auth state does not cause loops or blank screens.

Profiles

  • All required profile fields validate correctly.
  • Optional fields save correctly when left empty.
  • Editing a profile updates the correct user record only.
  • Multi-select values like languages and looking-for save and reload correctly.
  • Conditional fields like tribe, kids, and kids count show and hide correctly.
  • Long bios, unusual names, and special characters do not break layout or storage.
  • Numeric fields reject invalid values.
  • Saved profile data displays correctly on profile and detail pages.

Photo Uploads

  • Only JPG, PNG, WEBP, and GIF uploads are accepted.
  • The 8 MB file-size limit is enforced correctly.
  • Uploading one to five photos works without corruption.
  • Uploading more than five photos is blocked.
  • Primary photo selection saves correctly.
  • Failed Bunny uploads show readable error messages.
  • Slow uploads do not freeze the UI.
  • Broken or missing image URLs fail gracefully.

Dashboard and Discovery

  • The dashboard loads matching profiles and never shows the current user as a card.
  • Opposite-sex filtering behaves correctly for all supported profile combinations.
  • Empty-state messaging appears correctly when no profiles match.
  • Profile cards render correctly with and without photos.
  • Clicking a card opens the correct profile detail page.
  • Religion, location, and looking-for filters work alone and in combination.
  • Filter state persists correctly for the current user.
  • Dashboard remains usable with larger profile counts.

Likes and Messaging

  • Users cannot like themselves.
  • Duplicate likes are blocked.
  • Like counts and like badges update correctly.
  • New chat threads are created only once for a user pair.
  • Existing chat threads are reused instead of duplicated.
  • Messages appear in the correct thread for both users.
  • Long messages, empty messages, and special characters are handled safely.
  • Unread counts and seen-state tracking stay in sync with actual messages.

Membership and Premium

  • Free users get free limitations only.
  • Premium users get all paid benefits everywhere in the app.
  • The dashboard upgrade button appears only for signed-in non-premium users.
  • Clicking upgrade marks the user as premium immediately.
  • Premium users no longer see the upgrade button.
  • Ads disappear after premium activation.
  • Profile highlighting and premium badges render consistently.
  • Legacy silver, gold, and platinum records resolve to premium correctly.

Security and Authorization

  • Signed-out users cannot write protected data.
  • Users cannot read or modify another user’s restricted records.
  • Firestore rules match actual app behavior for every collection.
  • Users cannot grant themselves premium by tampering with requests unless explicitly allowed.
  • Upload validation is enforced server-side, not just in the browser.
  • Stored XSS is blocked in names, bios, messages, and location fields.
  • Error messages do not leak secrets or sensitive server details.
  • Spam and abuse cases are tested for likes, messages, signups, and uploads.

Data Integrity

  • Email normalization is consistent across all collections.
  • Account, profile, membership, likes, and chat data all link to the same user identity.
  • Concurrent updates from two tabs do not silently overwrite critical data.
  • Membership changes update only the intended record.
  • Refreshing the app does not duplicate likes, threads, or messages.
  • Bad query params do not load the wrong profile or thread.
  • Local mode and Firebase mode do not hide production-only failures.
  • Corrupt or missing Firestore documents fail safely.

UX and Accessibility

  • All pages work on desktop, tablet, and mobile.
  • Sticky header and top actions do not overlap content.
  • Menus, forms, and modals are keyboard accessible.
  • Visible focus states exist for all interactive elements.
  • Escape closes menus and modals where expected.
  • Text contrast remains readable across all screens.
  • Error states and loading states are clear and understandable.
  • Long names, long locations, and missing photos do not break layout.

Performance and Launch Ops

  • First load time is acceptable on slower mobile networks.
  • Dashboard and chat remain responsive with realistic production data volume.
  • Firestore reads are measured so cost is understood before launch.
  • Image sizes are optimized enough for mobile use.
  • Server logs capture upload failures and unexpected runtime errors.
  • Frontend errors are tracked somewhere in production.
  • Monitoring exists for uptime, latency, and failed requests.
  • Rollback and recovery steps are documented and tested.
